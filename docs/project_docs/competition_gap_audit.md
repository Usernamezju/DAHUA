## 2. 本次发现并修复的工程缺口

1. 自动进化 YAML 使用了已废弃的 `{data_root}/NTU/...` 路径，导致实际存在
   的 `datasets/NTU/ProtoGCN/ntu120_3danno.pkl` 永远被报告为缺失。现已把
   当前路径放在候选路径首位，并保留旧路径兼容。
2. Web 默认教师命令此前不能直接配置 dtype。现已支持
   `--qwen-model-dir`、`--qwen-dtype`、`--qwen-device-map`、注意力后端、
   帧数、生成长度和重试次数，并把实际模型目录与 dtype 写入教师产物溯源。
3. 当前默认教师配置已调整为 Qwen3-VL-8B-Instruct + FP16。32B 仍可通过
   命令行覆盖，不影响历史产物。
4. 原验收程序只检查单个 checkpoint 的大小，不能证明完整边缘包小于
   50MiB。现在 `--edge-model` 可重复传入，并对所有文件求和。
5. 新增 `pipeline.evaluate_predictions`，统一生成 Accuracy、Macro-F1、每类
   Precision/Recall/F1/FPR、混淆矩阵、ECE、Brier、P50/P95/P99 时延、
   遮挡/视角/光照分组和模型包大小报告。
6. 服务器 PyTorch 1.10 的 CPU FP16 不支持部分 `clamp_min` 操作；STN 几何
   函数现用 FP32 计算后恢复 FP16，避免验收测试因旧环境能力缺失失败。
7. 资源脚本新增 MediaPipe Lite 下载选项，并修复 `--data-root` 覆盖后
   `model-root` 仍指向旧目录的问题。

## 3. 尚未实现为最终参赛产物的部分

### 3.1 Campus6 六分类模型权重

代码具备六分类数据构建、微调和蒸馏能力，但没有满足六类定义的人工训练集，
因此没有可发布的 Campus6 checkpoint。KTH 的动作标签以及 BEHAVE 的 Chase、
Fight 等粗标签不能自动等价为“嬉戏/冲突”六分类真值。

实施方案：

1. 从官方数据和候选视频建立按原视频分组的数据划分，避免相邻片段泄漏。
2. 先人工标注每类至少 100 条训练样本，并建立独立 calibration、validation、
   test；危险类和易混淆类优先。
3. 使用 NTU120 ProtoGCN 去掉分类头后的 checkpoint 初始化六类模型。
4. 第一阶段仅用人工标签微调，建立可信 baseline。
5. 第二阶段加入人工校准后的 Qwen 伪标签、难例和回放样本进行蒸馏。
6. 只在固定 test 上比较，不把 test 数据用于阈值、早停或伪标签筛选。

### 3.2 完整边缘包 ≤50MiB

服务器现有文件：ProtoGCN 32.10MiB、MediaPipe Heavy 29.25MiB、NanoDet
3.79MiB。即使关闭 NanoDet，前两项总和也约 61.35MiB，不能按完整边缘包
口径宣称达标。

实施方案：下载 MediaPipe Pose Landmarker Lite，保持 NanoDet 默认关闭，
重新评估 Lite 对小人、遮挡和双人视频的骨架质量与六类准确率。只有完整包
求和和准确率都通过后才能替换 Heavy。若 Lite 精度不满足，再对 ProtoGCN
做 FP16 weight-only/ONNX 压缩，并重新验证数值一致性。

### 3.3 提交材料

仓库已有系统实施方案、模块文档、README、验收脚本和本用户手册；仍缺少
基于最终真实实验结果的算法测试报告、数据集许可/版本声明、汇报 PPT 和
10 分钟内演示视频。这些材料必须在 Campus6 模型与固定测试结果产生后完成，
当前不能用 Mock 或 NTU120 联调结果代替。

## 5. 需要向赛事方确认的合规口径

- “模型大小 ≤50MB”是只计算最终行为学生模型，还是计算姿态模型与行为模型
  的完整边缘包；本项目按更严格的完整包口径准备验收。
- 命题写有开发语言限 Python/C/Rust，而当前 Web 可视化使用原生 JavaScript。
  核心算法全部为 Python，但仍需确认可选展示层是否允许 JavaScript；若不允许，
  提交包应排除 Web 前端并使用 Python CLI/本地渲染演示。
- 服务器 `skel_gcn38` 为兼容上游 ProtoGCN/MMCV 使用 PyTorch 1.10，低于命题
  建议的 PyTorch 2.0+。应确认“2.0+”是否为硬门槛；若是，需单独建立 PyTorch
  2.x 推理导出环境并完成数值一致性回归，不能直接升级旧训练环境。
- KTH、BEHAVE、LIMU、NTU RGB+D 等外部数据的版本、用途、许可证和下载地址
  必须进入最终数据集说明，不能只在命令或目录名中出现。

具体命令与输入格式见 [算法测试指南](algorithm_test_guide.md)。
