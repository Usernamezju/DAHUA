# Campus6 最终成品验收清单

本清单以 Notion《系统设计文档》第 2、4、5、6、7、8、9、10、17 章为唯一功能边界。

## 产品定位

Web 是 Campus6 校园行为识别系统的交付界面，不是数据集筛选或 RGB 上传工具。它复用原有深色仪表盘的视觉语言，但面向持续运行的识别服务：用户查看自动产生的结果、处置高风险事件、理解模型依据并追溯模型更新。

## 不可违反的边界

- 浏览器仅接收 Skeleton 视频、结构化骨架语义、预测与审计结果；不得传输、播放或保存原始 RGB 视频。
- 原始视频只允许在边缘侧的 RTMDet-S INT8 + RTMPose-S 流程中短暂使用，输出标准 `COCO-17`、最多两人的骨架序列。
- 正式线上学生模型是 `M1KD QAT INT8 + Logits KD`（5.31 MiB，Test 46/53，All 345/358）；FP32 GAP ProtoGCN 只用于训练、回归与重蒸馏。RTMDet-S/RTMPose-S 与既有 M 特征都遵循同一 COCO-17 契约，因此不重建历史骨架。
- Qwen3-VL-8B-Instruct 只能接收骨架视频、结构化语义图与学生 Top-K。它在单张满足空闲阈值的 GPU 上按需加载，绝不下载模型到本地。
- KTH、LIMU、BEHAVE、MediaPipe/NTU 历史候选库不得作为 Web 数据源。

## 基线与增量数据

- 初始正式基线：`annotations_with_all.pkl`，包含当前 Campus6 模型使用的 358 条 COCO-17 骨架样本，划分为 Train 252 / Val 53 / Test 53。
- 数据集以 GitHub Release 资产发布（`campus6-data-v1.0.0` → `campus_all_release_20260905.tar`），下载并校验解包：`bash scripts/download_dataset.sh`，解包至 `dataset/campus_all/`。
- 第 9 章的 300 条不是初始数据集总数，而是一次增量训练批次：50 条新难例 + 250 条类别均衡历史样本。
- 线上审核、Qwen 结果、人工标签与候选模型均使用独立运行目录，不能污染初始基线标注。

## 成品界面（保留原页面视觉风格）

1. **系统总览**：边缘处理状态、当前 M1KD 版本、Qwen GPU 准入、近期事件、六类统计和端到端延迟。
2. **行为识别结果**：Skeleton 视频、M1KD 六类 Top-K、最终融合标签、置信度、姿态质量和事件时间线；页面不提供 RGB 上传、RGB 预览或手动运行按钮。
3. **语义理解与依据**：展示 Qwen 的触发原因、输入摘要、六类分布、一句话依据、Student/Teacher 一致性与人工复核原因。
4. **Skeleton 隐私模式**：说明并展示仅骨架的数据流、关键点质量、双人跟踪状态和隐私边界。
5. **模型与闭环**：FP32→QAT+Logits KD→M1KD INT8 的版本关系；难例积累、50/250/300 增量批次、候选评测、人工发布与回滚状态。
6. **审计记录**：人工复核的最终标签、理由、备注、学生/教师快照和不可变事件记录。

## 后端持续链路

`edge video -> RTMDet/RTMPose GPU -> COCO-17 skeleton -> M1KD INT8 GPU -> gate -> Qwen3-VL-8B (if needed) -> fusion / review -> audit / incremental queue`

- 服务启动后自动消费已注册的 Campus6 骨架任务；浏览器只观察状态和提交人工结论。
- 难例与 Qwen 的前置门控：学生 Top-1 置信度必须不高于 0.30；高于 0.30 时五项难例条件全部抑制且禁止调用 Qwen。通过前置门控后，再检查 Top-1/Top-2 间隔、教师分歧、高置信冲突、时序不稳定与类别稀有。
- 融合规则：一致则自动确认；学生不确定且教师明确则采用教师；双方高置信冲突、教师不可用/异常、输入质量不足时进入人工审核。
- 增量训练永远从 FP32 基线开始，经过评测后重新生成 INT8 候选；只有人工发布才能切换线上部署模型。

## 发布前验证

- 不存在任何 RGB Web API、上传控件或原始路径泄露。
- 358 条初始 Campus6 骨架可被注册、展示和离线推理；增量训练的 300 条策略可审计。
- RTMDet/RTMPose 与 M1KD 均使用智能选择的 CUDA GPU；不静默回退 CPU。
- Qwen3-VL-8B 在 GPU 准入通过时可真实完成结构化输出；未通过时明确路由到人工审核。
- UI、API、训练/蒸馏脚本、测试和 README 的模型名称与职责一致。
